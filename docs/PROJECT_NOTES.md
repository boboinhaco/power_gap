## 1. 한 줄 정의

전력거래소(KPX)가 전날 발표하는 **하루전 수요예측**이 내일 저녁(18~21시)에 실제와 얼마나, 어느 방향으로 빗나갈지를 **전날 저녁에 미리 예측**하여, 그 오차에 손익이 걸린 사업자에게 **사전 경보**를 제공하는 B2G·B2B 서비스.

- 예측 대상은 "수요 자체"가 아니라 **"공식 예측의 오차(잔차)"** 이다. (머신러닝 용어로 잔차 학습, residual learning)
- 사후 평가("예측이 맞았는지 확인")가 아니라 **사전 예측**이다.
- 발전량 예측은 다루지 않는다. 수요(사용) 예측의 오차만 대상이다.

### 1.1 왜 수요를 직접 예측하지 않는가

- 전력거래소는 이미 LSTM 포함 자체 모델(KSLF)로 수요를 예측한다. 학생 모델이 3일 만에 그걸 이길 가능성은 거의 없고, 이기지 못하면 "왜 당신 모델을 쓰냐"에 답이 없다.
- 오차는 공식 모델이 **놓치는 부분(숨은 태양광, 기온 급변)** 만 담고 있어, 작은 모델로도 "공식 예측보다 덜 틀리게" 만들 여지가 있다.
- 비유: 기상청이 "내일 28도"라고 예보하는데 우리 동네는 늘 2도 더 덥다 → 우리는 "+2도"를 맞히는 모델이다.
- 흐름 비교: 일반 방식 `실적 → 모델 → 내일 수요` / 우리 방식 `(공식 예측 − 실적) → 모델 → 내일 오차 → 공식 예측에 더해 보정`
- 공식 예측 데이터(①)는 **정답을 계산하는 재료이자 입력**이다. 없으면 정답 자체를 못 만든다.

## 3. 핵심 개념 정리 (논의 Q&A)

### 3.1 "손실 5%"와 우리가 말하는 "갭"은 다른 것이다

| 구분 | 성질 | 우리 모델과의 관계 |
|---|---|---|
| 송배전·소내 손실 (약 3.5~5%) | 매일 거의 일정, 물리적으로 계산 가능, 공식 예측에 이미 포함 | 예측 대상 아님 (상수) |
| 시장수요 vs 총수요 차이 (약 8GW) | 한전PPA·자가용 태양광의 "숨은 수요", 날씨 따라 매일 변동 | 오차의 주요 원인 |
| 하루전 예측 vs 실적 오차 | 날마다 크기·방향이 바뀜 | **우리 모델의 타겟** |

핵심은 평균 크기가 아니라 **변동성**이다. 매일 같은 값이면 모델이 필요 없고, 매일 바뀌기 때문에 전력거래소가 운전예비력 1,500MW를 상시 대기시킨다.
발표용 한 줄: "손실은 상수라 공식 예측에 포함됨. 우리는 그 위에 남는 **변동 오차**를 다룬다."

### 3.2 전력거래소(KPX)의 세 가지 역할, 그리고 왜 한전이 아닌가

1. **채점 대상 예측의 주인**: 매일 전날 "발전계획용 수요예측"을 발표. 발전 계획·하루전시장 가격·예비력 확보의 기준.
2. **데이터 제공자**: 예측값(kpx.or.kr)과 실적(공공데이터포털)을 모두 제공.
3. **1순위 고객(B2G)**: 예측 오차에 대비해 운전예비력을 대기시키는 계통운영 부서.

- 교수님이 "한전의 목표"라고 하신 것은 전력당국 전체를 느슨하게 말씀하신 것. 하루전 수요예측·급전 운영 주체는 **전력거래소**, 한전은 송배전·판매.
- 전력거래소는 자체 수요예측팀과 모델(KSLF)이 있어 "판다"보다 "보완 제안"이 현실적. 과제 평가상 B2G 허용(0.2)이므로 1순위로 둠.
- 해외 Amperon·Yes Energy가 ISO 예측을 보완해 ISO와 시장참여자에게 파는 것과 같은 구조.
- 표현 주의: "전력거래소 예측이 틀렸다" ✗ → "공식 모형(KSLF)이 구조적으로 처리하기 어려운 BTM 태양광 부분을 **보완**한다" ✓

### 3.3 데이터 사용 가능 여부

- 전국/제주 전력수요량 CSV: 공공데이터포털 공개 파일. 보통 공공누리 1유형(출처표시, 상업적 이용 가능). **(확인 필요)** "이용허락범위" 캡처.
- 수요예측 xlsx: 전력거래소 홈페이지 "전력관련정보" 공개 자료. 로그인 불필요.
- README·발표자료에 "출처: 한국전력거래소, 공공데이터포털(데이터셋 15065266)" 명시.
- 수업용 주식 데이터 대신 실제 공개 데이터를 쓰는 것은 Q&A 2의 "포트폴리오로 변환" 취지에 정확히 맞음.

### 3.4 제주 VPP·ESS는 무엇인가 (공급 측)

- **VPP(가상발전소)**: 소규모 태양광·풍력·ESS를 수십~수백 개 묶어 하나의 발전소처럼 시장에 "내일 몇 MW 발전하겠다"고 입찰하는 집합사업자. 전기를 쓰는 쪽이 아니라 **파는 쪽**.
- **ESS 운영사**: 싼 시간에 충전, 비싼 시간에 방전. 충전 시에만 수요 역할, 본업은 방전(공급) 입찰.
- 한국은 한전 단일 구매자 구조라 소비자가 전기를 사려고 입찰하지 않는다. "사용할 전기를 입찰"이라는 설명은 틀렸다.

### 3.5 제주 전력시장 구조와 손익 발생 지점

- 육지: 하루전시장만 운영. 15분 실시간시장·예비력시장은 **제주 시범** 단계(2024년~). 전국 확산 여부는 제주 실증 결과에 달림.
- 제주 흐름: ① 전날 하루전시장 입찰 → ② 낙찰 물량·가격 확정 → ③ 당일 실제 공급량과의 편차를 **실시간 가격**으로 정산 → ④ 실시간 > 하루전이면 손해.
- 손익 = (하루전 가격 − 실시간 가격) × 편차량.
- 미국에 Amperon 고객이 150개+인 이유는 하루전·실시간 가격차로 돈 버는 트레이더가 많기 때문. 한국은 그 구조가 제주에만 있음 → 국내 서비스가 없는 이유가 "기회"가 아니라 "살 사람이 없어서"일 가능성을 솔직히 병기.

### 3.6 우리 서비스와 제주 고객의 연결 고리 (약점 포함)

- VPP의 **편차량**은 그들 자신의 발전 예측 실패에서 나온다. 우리는 이것을 예측하지 않는다.
- 우리가 예측하는 공식 **수요예측 오차**는 **가격 쪽**에 영향: 과소예측(실제 > 예측) → 실시간 가격 상승 방향.
- 즉 "편차가 얼마일지"가 아니라 "그 편차가 **비싸게 정산될지 싸게 정산될지**"를 미리 알려준다.
- PDF 4번 계산 틀은 이 둘을 한 식에 섞어 놓았으므로 발표 시 분리 설명.
- 페르소나 리뷰(구매 담당자 시점)에서 가장 큰 구멍으로 지적된 것: **공식 예측이 전국 단위라 제주 고객에게 메리트가 약하다** → 이 세션에서 **제주 단위 예측(pssJeju)·실적 확보로 해소**됨.
- **(확인 필요)** 공식 수요예측 오차와 제주 실시간 가격 편차가 같은 방향으로 움직이는지 데이터 검증. 상관이 없으면 제주 B2B 고리가 끊어지고 B2G만 남는다.

### 3.7 "하루 전"이 메리트가 있는가

- 전력 산업은 애초에 하루 단위로 돌아간다. 하루전 예측·입찰·발전계획이 전날 정해지므로 "하루 전"은 늦은 게 아니라 **기본 의사결정 주기**.
- 하루 전이 맞는 고객: ESS 운영사·DR 사업자(전날 저녁에 내일 스케줄 작성), 대규모 소비기업(최대부하 15~21시 생산 스케줄 조정).
- 하루 전이 약한 고객: 화력 발전사(중앙급전 지시를 받는 입장이라 행동 여지 작음) → **초기 고객 설정 오류, 제외함**.
- 구매 메리트는 예측 시점보다 **"공식 예측보다 얼마나 덜 틀리냐"** 로 결정 → 게이트를 베이스라인 대비 개선율로 두는 것이 운영 설계이면서 영업 논리. 개선율 0이면 살 이유가 없고, 그걸 숨기지 않는 것이 비판적 사고.

### 3.8 타이밍 함정과 서비스 포지션 (중요)

- 하루전시장 입찰 마감(D-1 오전, **확인 필요: 10시 또는 11시**)은 공식 수요예측·하루전 SMP 공표보다 **앞선다**.
- 따라서 우리 모델은 하루전 입찰을 바꾸는 데 쓸 수 없다. **"하루전 입찰 최적화 서비스"라고 하면 안 된다.**
- 올바른 포지션: **"하루전시장 청산 후, 내일 실시간 가격 편차가 커질 시간대를 미리 경보한다."**
- 고객의 실제 행동: 실시간시장 **변경입찰** 검토(마감: 해당 구간 시작 75분 전, 확인 필요), **ESS 운전계획 조정**, 가격노출 위험관리.
- 사후 라벨 확정: 확정 실시간가격은 D+1 18시까지 공표 (확인 필요). 수요 실적은 당일~익일 확정.

5. 누적형 파일 중복 날짜 dedup
6. 헤더 `1시…24시` vs `1h…24h` → hour 1~24. 24시 = 23:00~24:00 구간
7. macOS 한글 파일명 NFD → `unicodedata.normalize('NFC')` 매칭 (`glob` 실패함)
8. xlsx: openpyxl 없이 zip+XML 파싱, 날짜 열 sharedStrings(`t="s"`) 처리
9. CSV 마지막 빈 행 제거

| \|오차\| > 10% 날 비율 | 5% |
| 어제와 방향이 뒤집힌 날 | 28% |

결론: 상수를 빼도 4.5%p가 남고 방향이 매일 바뀐다. **오차는 일정하지 않으며 서비스가 필요하다.** 추가 데이터(날씨)는 변동을 **설명**하는 피처 용도.

### 7.1 도메인 매핑표

### 7.2 베이스라인·승격 게이트

- (a) 오차 = 0 (공식 예측 그대로)
- (b) 어제 오차 그대로
- (c) 평균 오차 상수 (추가 권장) — "오차가 일정하면 서비스 불필요" 질문에 표 한 장으로 답
- **게이트: 재학습 모델 RMSE ≤ 베이스라인 RMSE × 0.9 (10% 이상 개선, 가정)**. 절대 RMSE 게이트는 "이미 잘 맞는 예측의 남은 2%"를 다루는 우리 일에 무의미.
- 지표: RMSE 기본 + **WAPE** 병행 (교수님 권고). 스프레드 타겟(B) 채택 시 임계치 초과·방향 분류 지표(정확도/F1) 보조.
- 스키마: `schemas.py`의 `close > 0` 제약을 **Field 수정으로 정석 해제**. "고정 오프셋 더하고 응답에서 빼기"는 꼼수라 시니어 리뷰에서 비추.

### 7.3 드리프트 값·임계치·시뮬레이션

```
실제 오차(정답)   e_actual = 공식 예측 − 실적
우리 모델 출력    e_pred
드리프트 RMSE   = sqrt( mean( (e_pred − e_actual)^2 ) )  over 최근 21일
임계치           = 같은 21일 구간에서 "오차=0" 베이스라인의 RMSE
판정             운영 RMSE > 베이스라인 RMSE  →  드리프트 (우리 보정의 개선 효과 소멸)
```

- HAIC의 "예측 종가 vs 실제 종가" 자리에 "예측 오차 vs 실제 오차"가 들어간다.
- 임계치를 상대 기준으로 두면 계절마다 MW 규모가 달라도 자동 추종. 게이트(×0.9)와 드리프트(×1.0)가 같은 기준을 비교하므로 HAIC의 "판단 두 번" 구조 유지.
- `simulate_drift.py`: 가격 랜덤워크 대신 **"흐린 날 연속 배치"** 주입 → e_actual 한쪽 쏠림 → RMSE 급등.
- 오탐 방지: 휴가철·명절 등 **특수일은 재학습 트리거에서 제외** (여름 산업체 휴가 하나로 약 5GW 빠짐). Q&A 6 "망각 방지" 논의와 연결.
- 오차 시계열은 계절성이 강해(5월·9월 증가) 21일 fine-tuning이 다음 달엔 다시 틀릴 수 있음 → 재학습 주기 설계가 발표 포인트.

### 7.4 운영 루프

```
예측 발행(D-1 저녁, 공식 예측 공표 후)
  → 실제값 확정(수요: 당일~D+1 / 가격: D+1 18시)
  → 오차 실제값 생성
  → 최근 21건 롤링 RMSE (특수일 제외)
  → 임계치(베이스라인 RMSE) 초과?
  → fine-tuning (Production 가중치에서, 스케일러 재fit 금지)
  → 게이트 재검증 (베이스라인 3종 대비 ≥10% 개선)
  → 캐시(_model_cache) 갱신 후 승격
```

- `POST /predict`: 예측 오차(MW), 오차 방향(과소/과대), 위험 등급, 모델 버전
- `GET /health`: 모델 상태 + **데이터 신선도**(마지막 실적 수신 시각)

### 7.7 고객별 활용과 비즈니스 밸류 (발표 순서: 모델 → 고객)

| 순위 | 고객 | 활용 | 계산 틀 |
|---|---|---|---|
| 1 (B2G) | 전력거래소 계통운영·수요예측 부서 | 오차 경보 → 운전예비력·급전 계획 최적화 | 오차 X MW 감소 → 대기 예비력 X MW 감축 → X × 대기시간(h) × 단위비용(원/MWh) = 연간 절감액. **단위비용 (확인 필요: 전력거래소 정산자료·에경연 보고서), 가정값 + 민감도(비용 2배면 결과 2배) 제시** |
| 2 (B2B) | 제주 VPP·ESS 운영사 | 청산 후 실시간 가격위험 경보 → 변경입찰 검토·ESS 운전계획 조정 | (하루전 가격 − 실시간 가격) × 편차량 = 회피 가능 손실 **(제주 실시간 정산 데이터 확인 필요)** |
| 3 (B2B) | 전국 DR 사업자 | 과소예측 예상일 = 감축 요청 가능성 ↑ → 자원 준비 | "있으면 좋음" 수준 |
| 플랜 | 대규모 전력 소비기업 | 교수님이 "B2B 너무 좁다" 하실 경우: 타겟을 "저녁 피크 위험 등급"으로 바꿔 생산 스케줄 조정 고객으로 확대 | 최대부하 15~21시 요금 회피 |

- 현실: 육지는 하루전시장만 → 민간 구매 수요는 소수. **"국내 첫 사례 선점"** 포지션이 정직한 말. "지금 다들 사려고 줄 선다"는 거짓.
- 발표 마무리 문장: "AIOps 구축"이 아니라 **"예비력 N MW 절감 = 연 N억"**.

### 7.8 확장 설계 (기획서에만, 구현은 시간 보고)

1. **당일 갱신 모델**: 실시간 수급현황(5분)으로 입력 시퀀스를 "최근 20일" → "최근 20시간"으로 바꾸면 같은 스켈레톤으로 "4시간 뒤 오차" 예측. "하루 전 계획 + 당일 보정" 2단계 → 제주 15분 시장 구조와 일치. "하루 전이 늦지 않냐" 질문의 답.
2. **LLM 사이드카**: 드리프트 로그를 LLM에 넘겨 "오늘 오차가 커진 원인 추정 보고서" 자동 생성. 교수님이 예시로 든 아키텍처라 가점 요소.
3. 상용 수준 격차 명시: 재학습 비동기 분리, 복제본 상태 조율, 아티팩트 저장소 분리, 로그 체계 → "우리 범위 밖"으로 기획서에 한 줄.

## 11. 발표 예상 질문과 답

| 질문 | 답 |
|---|---|
| 손실 5%가 있는데 갭이 의미 있나? | 손실은 상수라 공식 예측에 포함. 우리는 매일 바뀌는 변동 오차(제주 std 5%, 전국 2,000MW)를 다룸. |
| 오차가 항상 −4%면 그냥 빼면 되지 않나? | 상수를 빼도 RMSE 4.5%p 남고 26%는 방향이 반대. 베이스라인 (c)로 표 제시. |
| 왜 항상 과소예측인가? | 집계 기준 차이(손실·양수 등) 가능성. 정의 확인 예정. 모델은 상수 학습 가능. |
| 전력거래소 예측을 비판하는 건가? | 보완. KSLF가 근사 처리하는 BTM 태양광 부분을 메움. 해외 Amperon 등 동일 모델. |
| 왜 수요를 직접 예측하지 않나? | 전력거래소가 LSTM으로 이미 함. 학생 모델이 이길 수 없고, 오차(잔차)만 보정하는 게 작은 모델로 가치가 생기는 길. |
| 제주 VPP가 왜 사나? 입찰에 쓸 수 있나? | 하루전 입찰에는 늦음. 청산 후 실시간 가격위험 경보 → 변경입찰·ESS 운전계획 조정. |
| 하루 전이면 너무 늦지 않나? | 전력 산업의 기본 의사결정 주기가 하루 전. 확장으로 당일 갱신(20시간 시퀀스) 설계. |
| 시중에 없는 서비스인가? | 해외엔 있고(Amperon, 특허), 국내는 실시간시장이 제주에 생기며 이제 수요가 생기는 단계. 국내 첫 사례 선점. |
| 데이터 1년이면 충분한가? | 제주 2년 확보, 명절 2회 포함. 전국은 1년, 추가 확보 예정. |
| 데이터 써도 되나? | 공공데이터포털·KPX 공개 자료, 출처 표기. |
| 비즈니스 밸류 숫자는? | 예비력 1,500MW 중 X MW 감축 × 대기시간 × 단위비용. 단위비용은 가정값 + 민감도. |
| RMSE만 쓰나? | RMSE + WAPE 병행. 게이트는 베이스라인 대비 개선율. |
| 드리프트 값이 뭔가? | 우리 오차 예측의 오차(RMSE, MW, 21일). 임계치 = 같은 구간 오차=0 베이스라인 RMSE. |
